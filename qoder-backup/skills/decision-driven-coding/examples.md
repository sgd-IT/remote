## 引擎1案例：用户积分回收任务（风险倒逼）

自问："如果这段代码明天凌晨2点炸了，最可能因什么？且该问题什么无法被监控告警捕获"

```java
/**
 * [决策点] 为何分页回收≤1000条？
 *   - 风险：单次处理10万+过期数据导致JVM FullGC（监控盲区：任务状态仍为RUNNING）
 *   - 防御：1000条阈值依据JVM堆内存压测（证据：Report GC-20240710）
 */
public void recycleExpiredPoints() {
    // [决策锚点] DP-1（风险：FullGC，防御：监控processedCount）
    int processed = 0;
    while (processed < MAX_PER_RUN) {
        List<PointRecord> batch = queryExpiredPoints(lastId, 1000);
        processed += batch.size();
        monitor.reportProcessed(processed); // 关键：上报实时进度防"假RUNNING"
    }
}
```

## 项目实践四步法

1. **分析项目阶段与需求**：明确当前是新建功能、bug修复、性能优化还是重构，定位关键模块，结合项目文档预判风险与盲区
2. **基于项目上下文生成决策点**：调用对应引擎，但聚焦本次任务的关键路径
3. **将决策点嵌入项目代码**：在方法入口、条件分支、异常处理等关键逻辑处添加决策点注释，每个注释必须包含风险/盲区描述、防御措施和证据ID
4. **通过代码评审验证决策点**：PR 的 Commit Message 关联决策点编号；Reviewer 检查决策点是否覆盖核心风险、证据是否可追溯、防御措施是否可监控/可测试

## 关键指标

实施2周后，核心逻辑手写速度应反超AI生成速度（因建立"决策→代码"神经直连）。
