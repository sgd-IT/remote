# work-log 工作内容总结

用于持续记录工作内容与经验，最终可翻译成简历素材。核心原则：**每条记录都要能直接翻译成简历上的成果句**——动词 + 对象 + 方法 + 量化结果。

使用本 skill 时，输出开头标注【项目名·work-log】，项目名取当前工作区根目录名（如 hc-standard、remote-monitor）。

## 数据目录

默认统一数据目录 `d:\code\remote-monitor\work-log\`（跨项目共用、简历素材统一汇总；用户指定其他位置时以用户为准）：

```text
work-log/
├── 00-履历总表.md        # 一行一条总索引：日期｜项目｜角色｜关键词｜核心成果
├── 01-项目/              # 详细记录：一个项目/模块一个文件，追加式
├── 02-专题/              # 跨项目专题汇总：性能优化.md、线上故障复盘.md、技术选型.md 等
├── 03-踩坑手册.md        # 纯结论，按技术栈分区
├── 04-简历素材池.md      # 打磨好的成果句，按能力主题分组
└── 05-技能清单.md        # 技能母表：领域｜技能｜熟练度｜佐证
```

- 目录不存在时先按上述结构初始化（各文件含标题与用途注释）。
- 日期一律用 `YYYY-MM-DD`。

## 四种工作模式

### 模式 A：记录一条工作内容

触发："记一条"、"帮我记下来"、"今天做了……记一下"。

1. **收集素材**：用户描述为主；必要时看本会话改动的文件和相关 git 提交（只读 `git log` / `git diff`，不执行任何 add/commit）。
2. **按模板整理**（见下方"单条记录模板"），缺关键信息时一次问全：
   - 结果有没有量化数据？没有精确数字就用量级对比（如"P99 从 ~800ms 降到 ~120ms"）。
   - 角色是独立负责 / 主导 / 参与？负责的具体是哪部分？
   - 有没有踩坑和可复用结论？
3. **落盘（三处联动）**：
   - 追加到 `01-项目/<项目名>.md`（不存在则创建）；
   - 在 `00-履历总表.md` 表尾加一行索引；
   - 含踩坑结论时，同步追加到 `03-踩坑手册.md` 对应技术栈分区。
4. 把写入的完整条目贴回给用户过目。

### 模式 B：按时间段汇总工作内容（日报/周报口径）

触发："总结今天/这周做了什么"、"写个周报"。

1. **拉代码侧素材**（主工作区 d:/code/remote-monitor 的三个仓库，只读；在其他项目使用时替换为当前工作区的实际仓库）：

   ```powershell
   git -C "d:/code/remote-monitor/anwei-fire-remote-monitor" log --since="7 days ago" --date=short --pretty="%ad %s"
   git -C "d:/code/remote-monitor/anwei-fire-remote-monitor-vue" log --since="7 days ago" --date=short --pretty="%ad %s"
   git -C "d:/code/remote-monitor/anwei-fire-remote-monitor-mobile" log --since="7 days ago" --date=short --pretty="%ad %s"
   ```

   - 时间范围按用户口径替换：`today 00:00`、`--since=2026-10-01 --until=2026-10-09` 等；需要改动细节时加 `--stat`。
   - 三个仓库分别对应：后端（Java / Spring Boot）、PC 前端（Vue3）、移动端（UniApp）。ponytail 等第三方目录不计入工作内容。
2. **合并记录侧素材**：`00-履历总表.md` 与 `01-项目/` 中该时间段的条目。
3. **去重合并**，按"项目/模块"分组输出。默认用**汇报口径**：大白话，讲完成什么、解决什么问题、带来什么价值；用户要"技术口径"时再补模块、文件与关键决策。
4. 默认只在对话输出、不落盘；用户说"存档"时写入 `02-专题/` 或用户指定文件。

### 模式 C：提炼简历素材

触发："更新简历素材"、"把最近的工作提炼成简历句"。

1. 读指定时间段的记录（默认最近一个月）。
2. 挑 3–5 条最有价值的（有规模、有数字、有决策的优先）。
3. 按公式改写：**动词 + 做了什么 + 用什么技术/方法 + 解决什么规模的问题 + 量化结果**。
4. 写入 `04-简历素材池.md` 对应能力主题分区。
5. 提醒用户：投不同岗位时用同一母池按 JD 裁剪重排，最相关的放最前，不一份简历通投。

### 模式 D：维护技能清单

触发："更新技能清单"。

1. 更新 `05-技能清单.md`：新技能标熟练度，"佐证"列必填（连回工作记录）。
2. 熟练度分级与"精通最多 2–3 个"的约束见 reference.md。
3. 月度同步：新学→加"了解"；常用→升级并补佐证；一年没碰→降级或删。

## 单条记录模板

```markdown
## <记录/模块名> · <日期范围>
> 项目：<所属项目名>
### 【类型】
功能开发 | 性能优化 | 故障排查 | 技术债 | 架构 | 协作
### 【背景】
为什么做，业务痛点
### 【方案】
关键技术决策 + 选型理由（为什么不用另一方案）
### 【我的角色】
独立负责 | 主导 | 参与（写明具体负责部分）
### 【结果】
量化数据；无精确数据用量级对比
### 【踩坑 & 根因】
现象 → 定位过程 → 根本原因
### 【可复用结论】
一句话原则，下次可直接复用
### 【关联】
Git commit / MR / 文档路径
### 【标签】
见"打标签维度"，一般 2–3 个
```

灵魂是最后三行：**可复用结论**是经验库的价值所在，**关联**保证半年后能找回上下文，**标签**支撑简历阶段的检索。

## 打标签维度

每条记录挂 2–3 个标签组合：

- **层级**：前端 / 后端 / 数据库 / 缓存 / 消息队列 / 基础设施 / 监控告警
- **技术栈**：Vue3 / Java / Spring Boot / MySQL / Redis / WebSocket / UniApp 等
- **动作类型**：从0到1 / 重构 / 性能优化 / 线上故障 / 技术选型 / 降本 / 带人
- **业务域**：告警 / 设备 / 值守 / 报表 / 权限 等

改简历时按"动作类型 + 技术栈"检索，可一次拉出所有同类战绩。

## 写作硬性规范

- 动词开头，动作 + 对象 + 方法 + 结果；禁止"负责 XX 开发"式名词堆砌。
- 结果优先量化；写不出数字就写量级和对比（"构建 12 分钟 → 3 分钟"）。
- 每条记录脱离上下文能独立读懂，不写只有当天才懂的缩写。
- 只记事实，不记流水账；同一天零散小事合并为一条。
- 当天记，不攒到周末补——细节会丢一半。
- **记录展示格式（2026-10-10 定稿）**：写入数据文件与对话输出统一版式——① 条目标题用 H2：`## <记录/模块名> · <日期范围>`（如 `## 消防告警分级响应系统 · 2026-10-08 ~ 10-09`，日期承载于标题，不使用 H1）；② 标题下紧贴一行项目名小标注：`> 项目：<所属项目名>`；③ 字段名（【类型】【背景】【方案】【我的角色】【结果】【踩坑 & 根因】【可复用结论】【关联】【标签】等）作为 H3 小标题突出显示（`### 【类型】`），内容紧跟其下一行，不与正文同级；④ 各块之间不插空行、整体紧凑；⑤ 更深层级按 H2→H3→H4 顺延、保持不跳级。
