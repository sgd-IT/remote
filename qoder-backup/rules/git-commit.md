# Git 提交与审核规则

## 提交或审核前必须询问
- 任何 `git commit` 操作之前，必须先向用户展示变更摘要（涉及的文件、改动要点），等待用户明确同意后才能执行提交。
- 任何代码审核（review）操作之前，也必须先询问用户并获得明确同意，不得自动发起。
- 未经用户确认，禁止自动执行提交或审核。

## 拆分最小粒度提交
- 禁止堆积大量修改后一次性提交。
- 必须拆分成最小的、逻辑独立的修改单元，逐个提交：一个提交只包含一个功能点、修复点或重构点。
- 原因：一次性提交内容过多，会导致后续查阅、回溯和 review 困难。

## 提交信息
- 提交信息需准确、简洁，说明该次单一变更的内容。
