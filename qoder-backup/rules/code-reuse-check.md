# 开发前复用检索规则

## 原则
实现任何功能（新功能、功能改造、修 bug）动手写代码之前，必须先检查当前框架/代码库中是否已存在可复用的实现。优先级：直接复用 > 扩展现有实现 > 新建。

## 动手前必须检索的内容
1. **同类业务实现**：是否已有相似的功能模块、流程、接口可以参照或直接调用。
2. **后端公共能力**：工具类（DateUtils、IdUtils、StringUtils 等）、通用 Service/Mapper 模式、公共 API 封装是否已有等价能力。
3. **前端公共能力**：
   - PC（ruoyi-ui）：是否已有同类组件、utils、mixins、公共弹窗。
   - APP（other1）：是否已有同类弹窗（pop 目录）、Adapter、Base 类、Bean 可改造复用。
4. **既有接口**：新增接口前，先确认能否通过给现有接口加参数/加方法满足，避免接口膨胀。

## 决策顺序
1. 直接复用现有实现；
2. 扩展现有实现（加参数/加方法/加配置），保持向后兼容；
3. 确实无法复用时才新建；新建必须遵循所在模块的目录结构、命名规范与代码风格惯例。

## 新建时的要求
- 用一句话说明"为何现有实现无法复用"。
- 新文件的结构、命名、注释风格与同目录现有文件保持一致，禁止引入与项目不符的新模式。

## 目的
避免重复造轮子、减少重复代码与维护面；保证新代码与现有框架风格统一、易于他人接手。
