## 1. 设计概述

### 1.1 设计愿景

**核心理念**：「告警驱动、数据支撑、合规护航」

智慧消防远程值守系统的UI/UX设计以「秒级响应」为核心理念，将传统的「数据罗列」模式转变为「告警驱动的决策支持」模式。所有界面设计围绕火警响应这一核心场景，确保值守人员在第一时间发现告警、判断性质、快速处置、全局掌控。

### 1.2 设计原则

| 原则 | 描述 | 实现方式 |
|------|------|---------|
| **告警优先** | 告警信息必须在视觉上最醒目 | 告警区域采用最高亮度、红色警示色、脉冲动画 |
| **操作高效** | 高频操作≤2次点击 | 大按钮、一键操作、快捷键支持 |
| **合规保障** | 界面体现合规要求 | 操作留痕提示、双人确认弹窗、超时提醒 |
| **角色感知** | 不同角色看到不同界面 | 权限驱动的动态导航、差异化首页 |
| **昼夜适配** | 暗色/亮色主题自动切换 | 值守大屏暗色默认、管理后台亮色默认 |

### 2.2 权限路由

#### 2.2.1 三级权限体系路由控制

| 权限等级 | 角色 | 可访问模块 | 默认首页 |
|---------|------|-----------|---------|
| L1 普通 | 值守员 | 大屏值守台、数据中心（查看）、视频监控 | 大屏值守台 |
| L2 操作 | 值守主管 | L1全部 + 远程控制台、运维工作台（值班相关）、查岗管理 | 大屏值守台 |
| L3 管理 | 技术负责人 | L2全部 + 运维工作台（全部）、系统管理 | 大屏值守台（综合视图） |

#### 2.2.2 路由守卫规则

```
路由守卫流程：
1. 用户登录 → 验证JWT Token有效性
2. 获取用户角色 → 查询权限配置
3. 路由匹配 → 检查目标页面权限
   ├─ 有权限 → 放行
   └─ 无权限 → 重定向至默认首页 + 提示"无访问权限"
4. 操作级权限 → 页面内按钮/操作权限控制
```

#### 2.2.3 权限控制组件

```vue
<!-- 权限控制组件使用示例 -->
<PermissionGuard :requires="['alarm:verify']">
  <Button type="primary" @click="handleVerify">确认火警</Button>
</PermissionGuard>

<!-- 无权限时自动隐藏 -->
<PermissionGuard :requires="['alarm:verify']" :mode="'hidden'">
  <Button type="primary">确认火警</Button>
</PermissionGuard>

<!-- 无权限时显示禁用态 -->
<PermissionGuard :requires="['alarm:verify']" :mode="'disabled'">
  <Button type="primary" disabled>确认火警</Button>
</PermissionGuard>
```

### 2.3 用户状态管理

#### 2.3.1 登录状态

| 状态 | 表现 | 处理 |
|------|------|------|
| 正常登录 | 显示用户头像和名称 | — |
| 会话超时 | 弹出登录框遮罩层 | 用户重新输入密码 |
| Token过期 | 自动刷新Token | 刷新失败则跳转登录 |
| 多端登录 | 提示"账号在其他设备登录" | 确认后强制登出 |

#### 2.3.2 证书状态提醒

| 证书状态 | 界面表现 | 处理方式 |
|---------|---------|---------|
| 有效 | 绿色✓标识 | 正常操作 |
| 30天内到期 | 黄色⚠提示条 | 顶部提示+站内信 |
| 7天内到期 | 橙色⚠提示条 | 顶部提示+短信通知 |
| 已过期 | 红色✕禁止登录 | 跳转证书上传页面 |
