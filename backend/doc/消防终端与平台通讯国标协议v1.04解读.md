## 一、文档总体概览

这是一份**大华消防产品线**的终端与平台间通讯协议，基于 **GBT26875.3-2011《城市消防远程监控系统 第3部分：报警传输网络通信协议》** 的补充协议。文档涵盖 **三套并行协议**：

| 章节 | 协议 | 适用平台 |
|------|------|----------|
| 第2章 | **TCP/UDP 协议**（大华定制） | 自建平台，直连通信 |
| 第3章 | **CoAP 协议** | 电信 IoT 平台 |
| 第4章 | **LwM2M 协议** | 移动 OneNET 平台 |

三套协议的**应用数据单元（ADU）格式完全一致**，差异仅在帧头和传输层封装。

## 二、核心数据模型（三协议共用）

### 2.1 帧结构核心概念

所有协议帧都由以下核心单元组成：

```
控制单元 + 应用数据单元(ADU) + 校验和
```

**控制单元** 关键字段：
- **命令字**（1Byte）：标识帧的大类（注册/数据上报/请求/操作/确认等）
- **应用数据单元长度**

**应用数据单元(ADU)** 采用 **TLV（Type-Length-Value）** 结构：
- **类型标志**（Type）：标识数据类型
- **信息对象数目**（Length）
- **信息对象**（Value）= 信息体 + 时间标签

### 2.2 命令字总表（开发核心）

| 命令字 | 方向 | 说明 |
|--------|------|------|
| `0x00` | 终端→平台 | 注册帧（可被通用帧替代） |
| `0x01` | 平台→终端 | 时钟同步帧 |
| `0x02` | 终端→平台 | 部件状态帧 |
| `0x03` | 终端→平台 | 部件模拟量帧 |
| `0x04` | 终端→平台 | 系统状态/模拟量/参数同步等 |
| `0x05` | 平台→终端 | 参数查询/设置/消音/通用下发 |
| `0x06` | 双向 | 否认帧 |
| `0x07` | 终端→平台 | 保活帧 |
| `0x87` | 终端→平台 | **通用数据帧**（推荐，可替代所有上报帧） |
| `0x88` | 平台→终端 | 查询通用帧 |
| `0x89` | 平台→终端 | 设置/配置通用帧 |
| `0x8E` | 终端→平台 | 确认帧 |

### 2.3 一级数据类型（TLV通用帧核心）

| 序号 | 数据类型 | 类型字 |
|------|----------|--------|
| 1 | 注册包类型 | 0 |
| 2 | **事件类型** | 1 |
| 3 | **模拟量类型** | 2 |
| 4 | 参数类型（定长） | 3 |
| 5 | 参数类型（不定长） | 4 |
| 6 | 操作类型 | 5 |
| 7 | 升级 | 6 |
| 8 | **能力类型** | 7 |
| 9 | 确认类型（含参） | 8 |
| 10 | 加密类型 | 9 |

> **关键约束**：同一信息体内，数据类型需保持一致；但事件&事件相关模拟量、定长&不定长参数允许组合。

## 三、CoAP 协议详解（第3章，开发重点）

### 3.1 CoAP 帧格式

```
┌──────────────┬──────────────┬──────────────────────────────────┐
│ 业务流水号(2B) │ 数据帧长度    │  数据包（字符串形式）              │
│  大端传输     │              │  含：控制单元 + ADU + 校验和       │
└──────────────┴──────────────┴──────────────────────────────────┘
```

**与TCP/UDP的关键差异**：
- CoAP帧**没有**启动符/结束符、协议版本号、时间标签、源/目的地址等字段
- 业务流水号按**大端**传输（TCP/UDP是小端）
- 数据包以**字符串**形式承载（适配电信IoT平台的Profile机制）
- 帧更精简，去掉了TCP/UDP帧中的冗余控制字段

### 3.2 CoAP 支持的完整命令列表

#### 上行（终端→平台）

| 命令 | 命令字 | 类型标志 | 说明 |
|------|--------|----------|------|
| 注册帧 | 0x00 | - | 设备首次接入 |
| 系统状态帧 | 0x02 | 0x01 | 系统状态变更上报 |
| 部件状态帧 | 0x02 | 0x02 | 部件状态变更上报 |
| 部件模拟量帧 | 0x03 | - | 周期上报部件模拟量 |
| 系统模拟量帧 | 0x02 | 0x84 | 周期上报系统模拟量 |
| 部件状态扩展帧 | 0x02 | 0x85 | 超8字节状态 |
| 部件模拟量扩展帧 | 0x03 | 0x86 | 超1字节类型模拟量 |
| **通用数据帧** | 0x04 | 0x87 | **推荐：统一上报帧** |
| 确认帧 | 0x03 | 0x8E | 对平台下发的应答 |

#### 下行（平台→终端）

| 命令 | 命令字 | 类型标志 | 说明 |
|------|--------|----------|------|
| 时钟同步帧 | 0x01 | 0x5A | 平台主动校时 |
| 设置参数帧（定长） | 0x04 | 0x64 | 配置设备参数 |
| 远程消音帧 | 0x04 | 0xF9 | 远程消音 |
| 查询通用帧 | 0x04 | 0x88 | 查询设备数据 |
| 设置/配置通用帧 | 0x04 | 0x89 | 通用下发指令 |
| 功能配置帧 | 0x05 | 0x81/0x82 | 操作命令 |

### 3.3 CoAP 注册帧格式（设备首次接入）

**终端→平台**：
```
协议版本号(2B) + 软件版本号(2B) + SN(16B,ASCII) + IMEI(8B,BCD) 
+ CCID(10B,BCD) + IMSI(8B,BCD) + CellID(8B,BCD)
+ 保活时间(4B) + 产品型号(16B,ASCII) + 额定电压(2B) + 欠压电压(2B)
+ TAU(2B) + 预留(14B)
```

**关键编码规则**：
- SN/产品型号：ASCII，大端，不足后补0
- IMEI/CCID/IMSI/CellID：BCD编码，大端，不足前补0
- 保活时间/电压：**小端**传输
- TAU取自NB模组的T3412和T3324定时器寄存器值

### 3.4 CoAP 通用数据帧（最重要的帧，可替代其他所有帧）

通用数据帧采用**多级TLV嵌套**结构：

```
┌────────────────────────────────────────────────┐
│ 应用数据单元长度(2B) + 命令字(1B=0x87)           │
│ 类型标志(1B) + 信息对象数目(1B)                   │
│ ┌─ 信息对象 ──────────────────────────────────┐ │
│ │ 部件类型(1B) + 部件地址(4B)                    │ │
│ │ 数据类型(1B) + 数据内容长度(2B) + 数据内容     │ │
│ │ 时间标签(6B)                                  │ │
│ └─────────────────────────────────────────────┘ │
└────────────────────────────────────────────────┘
```

**部件地址4B规则**：前2B为节点号，后2B为回路号（小端）。系统类终端填全0或全F。

**数据内容可嵌套**：当一级类型为事件/参数/能力时，数据内容包含下一级TLV结构。

## 五、通信模式总结

### 5.1 四种通信模式

| 模式 | 方向 | 机制 |
|------|------|------|
| 控制命令 | 平台→终端 | 发送/确认 |
| 信息上传 | 终端→平台 | 发送/确认 |
| 参数设置 | 平台→终端 | 请求/应答 |
| 信息查询 | 平台→终端 | 请求/应答 |

### 5.2 重发机制
- 超时时间 ≤ 30s
- 重发次数宜为 3 次
- 重发仍失败则本次通信结束

### 5.3 CoAP 特有注意事项
1. CoAP 帧**没有保活命令**（心跳通过部件状态帧/模拟量帧替代）
2. CoAP 帧**没有升级命令**（OTA通过电信IoT平台原生能力）
3. 通用数据帧（命令字0x04，类型标志0x87）是**推荐的统一帧格式**，可完全替代其他专用帧
4. 部件地址4B = 节点号(2B) + 回路号(2B)，小端
5. 业务流水号大端传输（与TCP/UDP的小端不同）
6. 数据包以字符串形式承载在CoAP帧中

## 六、能力类型体系

能力类型采用**二级/三级TLV结构**，描述设备支持的功能和参数范围：

### 数据类型分类
- **未定义类型**：仅代表功能有无（如设备判断报警、服务器地址）
- **Bool型**：TRUE/FALSE（如故障音能力、报警音能力）
- **整型**：有上限/下限范围（如烟雾浓度预警上限）
- **枚举互斥**：只能选一项（如灵敏度：高/中/低）
- **枚举**：可选多项

### 批量能力上报
- 一个信息体内只允许一个批量上报节点内容
- "批量上报的节点内容"（类型字65535）需在其他能力类型之后
- 平台只读取能力集(0)或全能力集(1)，不单独读取单个能力项

## 八、后续开发建议

基于这份协议，CoAP开发需要实现以下核心模块：

1. **帧编解码器**：CoAP帧的序列化/反序列化（注意大小端混合传输规则）
2. **注册管理**：设备注册帧解析 + 确认
3. **数据上报处理**：通用数据帧的多级TLV解析（事件/模拟量/参数/能力）
4. **下行指令**：参数设置、远程消音、查询、功能配置
5. **数据字典**：事件类型表、模拟量类型表、部件类型表、参数类型表、操作类型表、能力类型表的完整枚举定义
6. **时钟同步**：终端请求校时 + 平台下发校时
7. **字节序处理**：协议中大小端混合使用，需逐字段严格处理
