# YWN TCP V27 组件测试流程文档

## 1. 测试环境准备

### 1.1 前置条件

| 项目 | 要求 |
|------|------|
| JDK | 21.0.6 (Oracle LTS) |
| Maven | 3.8+ |
| 数据库 | MySQL / PostgreSQL (已初始化 `eiot_device_info`、`eiot_product`、`eiot_thing_model` 表) |
| Redis | 6.x+ |
| 测试工具 | Netcat / TCP 调试助手 / 自研模拟器 |

### 1.2 编译验证

```powershell
$env:JAVA_HOME = "D:\Java\jdk-21.0.6"
mvn clean compile -pl module-eiot/iot-components/iot-component-tcp-ywn -am -q
```

确认退出码为 0，无编译错误。

### 1.3 组件配置（数据库）

在系统组件管理界面新增组件记录：

| 字段 | 值 |
|------|-----|
| 组件类型 | `ywn-tcp` |
| 组件名称 | YWN控制器监控TCP协议V27组件 |
| 配置 JSON | 见下方 |

```json
{
  "host": "0.0.0.0",
  "port": 9200,
  "allowAutoRegister": false,
  "fallbackProductKey": ""
}
```

> **配置说明**
> - `host` / `port`：TCP 服务监听地址和端口
> - `allowAutoRegister`：`false` = 仅允许预注册设备接入；`true` = 未知设备自动注册
> - `fallbackProductKey`：仅 `allowAutoRegister=true` 时生效，作为自动注册的产品 Key

### 1.4 测试产品 & 设备准备

#### 场景 A：预注册模式（`allowAutoRegister=false`）

1. 在系统中创建产品（获取 `productKey`）
2. 在 `eiot_device_info` 表或设备管理页面中预注册设备：
   - `dn` = 设备编号字符串（如 `"00001"`，对应 YWN 协议的设备编号 1）
   - `product_key` = 上述产品的 Key
   - `serial_no` = 设备序列号
   - `node_type` = 2（直连设备）

#### 场景 B：自动注册模式（`allowAutoRegister=true`）

1. 在系统中创建产品，记录 `productKey`
2. 将 `fallbackProductKey` 设为该产品的 Key
3. 无需预注册设备，组件会自动注册

## 3. 协议帧解析测试

### 3.1 帧格式说明

```
命令码(1B) + 设备编号(2B 小端) + 载荷(变长)
```

无帧头、无长度前缀、无校验和。帧长度由命令码查表确定。

### 3.2 上行帧测试（设备 → 服务端）

#### 3.2.1 心跳帧 (0x82)

```
Hex: 82 01 00  (命令码=0x82, 设备编号=1, 小端序)
帧长: 3 字节
```

| 验证项 | 预期 |
|--------|------|
| 服务端回复 | `0x83 01 00`（心跳应答 HEARTBEAT_ACK） |
| 设备状态 | 更新为在线 |
| Redis | `str:iotkit:device:lasttime:{deviceId}` 更新为当前时间戳 |

#### 3.2.2 事件上传帧 (0x80)

```
总帧长: 67 字节 = cmd(1) + deviceNumber(2) + payload(64)

载荷 64 字节结构:
[0]  eventTypeCode    1B    事件类型码
[1]  productType       1B    产品类型
[2]  channelType       1B    通道类型
[3]  reserved          1B    备用
[4-5] eventCode        2B LE 事件代码
[6-7] deviceType       2B LE 设备类型
[8]  machineNo         1B    机号
[9]  loopNo            1B    回路
[10] addressNo         1B    地址号
[11] channelNo         1B    通道号
[12-15] alarmValueFloat 4B   IEEE754 浮点
[16-17] alarmValueInt  2B LE 报警值×100
[18-23] eventTime      6B    年月日时分秒 (year=2000+byte)
[24-63] description    40B   GBK 编码说明文字
```

**测试用例 — 火警事件：**

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 构造 eventCode=0x01 (火警) 的 67 字节帧 | — |
| 2 | 发送到服务端 | 服务端回复 ACK (0x01) |
| 3 | 检查 `thing_model_message` 表 | 新增 `type=event, identifier=fire_alarm_event` 记录 |
| 4 | 检查属性缓存 | Redis 中 `event_code=1, event_name=火警`，且 `fire_status=true`（状态聚合派生） |
| 5 | 前端查看 | 设备日志页显示火警事件 |

**测试用例 — 故障事件：**

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 构造 eventCode=0x50 (总线设备故障) 的 67 字节帧 | — |
| 2 | 发送到服务端 | 服务端回复 ACK |
| 3 | 检查 `thing_model_message` 表 | `type=event, identifier=fault_event` |
| 4 | 检查属性缓存 | `fault_status=true`，且已有的 `fire_status` 不被覆盖（按 key 合并） |

**测试用例 — 反馈事件：**

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 构造 eventCode=0x1A (总线设备反馈) 的 67 字节帧 | — |
| 2 | 发送到服务端 | 服务端回复 ACK |
| 3 | 检查 `thing_model_message` 表 | `type=event, identifier=feedback_event` |
| 4 | 检查属性缓存 | `feedback_status=true`（发送 eventCode=0x1C 反馈撤销后变为 false） |

> 注：状态聚合派生规则（fire/fault/feedback/shield/start/supervisory 共 6 个总线状态属性）的完整用例见 `doc/ywn/YWN改造上线操作与测试流程.md` 第二部分 B 组。

#### 3.2.3 设备信息上传帧 (0x81)

```
总帧长: 46 字节 = cmd(1) + deviceNumber(2) + iccid(20) + imei(15) + hwVer(4) + swVer(4)
```

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 构造 46 字节设备信息帧 | — |
| 2 | 发送到服务端 | 服务端回复 ACK (0x01) |

| 4 | 前端设备详情 | 显示 ICCID / IMEI / 硬件版本 / 软件版本 |

#### 3.2.4 控制器故障帧 (0x86)


| 属性缓存 | `controller_fault_status=true` |

#### 3.2.5 控制器故障恢复帧 (0x87)

#### 3.2.6 控制应答帧 (0x01 ACK)

```
Hex: 01 01 00  (共 3 字节)
```

| 验证项 | 预期 |
|--------|------|
| 服务端日志 | `[YWN] 收到控制应答: deviceNumber=1` |
| 不做其他处理 | — |

### 3.3 下行帧测试（服务端 → 设备）

> **改造说明**：物模型服务已由原 15 个独立服务收敛为**单一 `remote_control` 服务**，通过 `command_code` 参数区分命令。参数槽位固定为 4 个：`command_code`（2~17）、`machineNo`（默认 1）、`param1`（默认 0）、`param2`（默认 0）。

通过系统前端远程控制（厂商指令字典路由）或 API 调用 `serviceInvoke` 触发下行控制。

#### 3.3.1 remote_control 服务与命令码对照表

```
API 参数示例（复位）:
{ "serviceName": "remote_control", "params": { "command_code": 2, "machineNo": 1, "param1": 0, "param2": 0 } }
下行帧: 命令码(1B) + deviceNumber(2B LE) + 载荷 (共 15 字节)
```

| command_code | 命令 | param1 含义 | param2 含义 |
|------|------|------|------|
| 2 (0x02) | 设备复位 | — | — |
| 3 (0x03) | 消音 | — | — |
| 4 (0x04) | 总线设备启动 | 回路号 | 地址号 |
| 5 (0x05) | 总线设备停止 | 回路号 | 地址号 |
| 6 (0x06) | 手自动转换 | 模式 (2=手动, 3=自动) | — |
| 7 (0x07) | 屏蔽 | 回路号 | 地址号 |
| 8 (0x08) | 取消屏蔽 | 回路号 | 地址号 |
| 9 (0x09) | 自检 | — | — |
| 10 (0x0A) | 多线盘启动 | 盘号 | 路号 |
| 11 (0x0B) | 多线盘停止 | 盘号 | 路号 |
| 12 (0x0C) | 自动允许 | — | — |
| 13 (0x0D) | 自动禁止 | — | — |
| 14 (0x0E) | 手动允许 | — | — |
| 15 (0x0F) | 手动禁止 | — | — |
| 16 (0x10) | 自动手动允许 | — | — |
| 17 (0x11) | 自动手动禁止 | — | — |

**通用验证步骤：**

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 设备须在线 | — |
| 2 | 按上表逐条发起 `remote_control` 调用 | TCP 抓包（或 YwnClient 打印）收到 15 字节帧，命令码与表一致 |
| 3 | 检查 `thing_model_message` 表 | `type=service, identifier=remote_control_reply, code=0` |

#### 3.3.2 指令驱动状态清零

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 先制造火警/启动/反馈/监管状态 | 对应状态属性为 true |
| 2 | 下发复位 (command_code=2) | `fire_status/start_status/feedback_status/supervisory_status` 清零为 false |
| 3 | 先制造屏蔽状态后下发取消屏蔽 (command_code=8) | `shield_status=false` |

#### 3.3.3 非法命令码

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 调用 `command_code=99`（越界） | 返回 `ServiceReply(code=1)` |
| 2 | 检查 | `data={"error":"非法命令码: 99"}` |

#### 3.3.4 设备离线时下发命令

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 设备不在线 | — |
| 2 | 调用 `serviceName="remote_control"` | 返回 `ServiceReply(code=1)` |
| 3 | 检查 `thing_model_message` 表 | `identifier=remote_control_reply, code=1, data={"error":"设备不在线"}` |

#### 3.3.5 未知服务名

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 调用 `serviceName="unknown_service"` | 返回 `ServiceReply(code=1)` |
| 2 | 检查 | `data={"error":"未知服务: unknown_service, 仅支持 remote_control"}` |

## 6. 异常场景测试

### 6.1 畸形帧

| 场景 | 操作 | 预期 |
|------|------|------|
| 未知命令码 | 发送 `0xFF 01 00` | 帧被丢弃，日志告警，连接不中断 |
| 帧长不足 | 发送 2 字节（不完整帧） | 拆包器等待后续数据，超时后丢弃 |
| 事件帧载荷不足 | 发送 66 字节（应为 67） | 帧被丢弃或解析异常 |

### 6.2 并发连接

| 场景 | 操作 | 预期 |
|------|------|------|
| 多设备同时连接 | 10 个 TCP 客户端同时连接 | 各自独立注册，`clientMap` 正确维护 |
| 设备编号冲突 | 相同 deviceNumber 重连 | 旧连接被新连接替代 |

### 6.3 组件生命周期

| 场景 | 操作 | 预期 |
|------|------|------|
| 禁用组件 | 管理界面禁用 `ywn-tcp` | TCP Server 停止监听，日志 `TCP Server stopped` |
| 重新启用 | 修改配置并启用 | TCP Server 重新启动，新连接可接入 |
| 修改端口 | 更改 `port` 配置 | Verticle 重启，监听新端口 |

### 6.4 网络异常

| 场景 | 操作 | 预期 |
|------|------|------|
| 网络中断 | 拔网线 / kill 客户端进程 | TCP 连接断开，`onCloseCallback` 触发 clientMap 清理 |
| 服务端异常 | 模拟 NullPointerException | `exceptionHandler` 捕获，日志记录，不影响其他连接 |
