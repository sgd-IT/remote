# YWN控制器监控TCP协议 V27 对接项目

> 版本: V2.0.0 | 协议版本: V27 (2026-01-23) | 纯二进制帧，无Protobuf

## 一、协议概述

运维牛(YWN)控制器监控TCP协议V27，用于远控模块与监控平台之间的通信。

### 核心变更（对比旧版V1.0 Protobuf协议）
| 项目 | V1.0 (旧) | V27 (新) |
|------|-----------|----------|
| 数据格式 | Protobuf二进制 | 纯二进制帧 |
| 帧头 | 长度(2B)+命令(2B)+序列号(4B) | 命令码(1B) |
| 设备编号 | Protobuf字段 | 2字节LE |
| 事件数据 | Protobuf EventReq | 64字节固定结构 |
| 心跳 | 30秒 | 3分钟 |
| 新增命令 | - | 多线盘启动/停止、手自动允许/禁止等 |

### 帧格式
```
┌──────────┬──────────────┬───────────┐
│ 命令码(1B)│ 设备编号(2B LE)│ 载荷(变长)  │
└──────────┴──────────────┴───────────┘
```
- **无长度前缀**，帧长度由命令码查表确定
- 字节序: 小端(Little-Endian)
- 心跳周期: 3分钟
- 控制器故障判定: 2分钟无数据

## 三、事件数据结构 (64字节)

| 偏移 | 字段 | 字节数 | 说明 |
|------|------|--------|------|
| 0 | 事件类型码 | 1 | |
| 1 | 产品类型 | 1 | 0值不显示 |
| 2 | 通道类型 | 1 | 0值不显示 |
| 3 | 备用 | 1 | 0值不显示 |
| 4-5 | 事件代码 | 2 | LE, 0值不显示 |
| 6-7 | 设备类型 | 2 | LE, 0值不显示 |
| 8 | 机号 | 1 | 0值不显示 |
| 9 | 回路 | 1 | 0值不显示 |
| 10 | 地址号 | 1 | 0值不显示 |
| 11 | 通道号 | 1 | 0值不显示 |
| 12-15 | 报警值(浮点) | 4 | IEEE754, -1不显示 |
| 16-17 | 报警值(整型) | 2 | LE, 数据×100, -1不显示 |
| 18-23 | 时间 | 6 | 年月日时分秒, 0值不显示 |
| 24-63 | 说明文字 | 40 | GBK编码, 最多20个汉字 |

### 常见事件代码
| 代码 | 名称 |
|------|------|
| 0x01 | 火警 |
| 0x1A | 总线设备反馈 |
| 0x1C | 反馈撤销 |
| 0x50 | 总线设备故障 |
| 0x64 | 故障恢复 |

## 七、运行方式

### 启动服务端
```bash
mvn clean package
java -jar target/ywn-protocol-v2-2.0.0.jar [port]

# 默认端口8839
java -jar target/ywn-protocol-v2-2.0.0.jar
# 指定端口
java -jar target/ywn-protocol-v2-2.0.0.jar 9000
```

### 启动测试客户端
```bash
# 连接本地服务端, 设备编号1001
java -cp target/ywn-protocol-v2-2.0.0.jar com.anwei.ywn.client.YwnClient 127.0.0.1 8839 1001

# 连接YWN平台
java -cp target/ywn-protocol-v2-2.0.0.jar com.anwei.ywn.client.YwnClient ** 8839 1001
```

### 客户端交互命令
```
1  - 上报火警        6  - 上报设备信息
2  - 上报故障        7  - 发送心跳
```

实现 `YwnEventListener` 接口，将协议层事件对接到业务系统：

```java

    @Override
    public void onEvent(int deviceNumber, YwnEvent event) {
        // 对接物联网平台/物模型事件上报
        if (event.isFireAlarm()) {
            // 火警 → 告警推送 + 远程值守大屏弹窗
        }
    }

    @Override
    public void onDeviceInfo(YwnDeviceInfo deviceInfo) {
        // 设备上线 → 注册到设备管理表
    }

    @Override
    public void onControllerFault(int deviceNumber) {
        // 控制器离线 → 故障告警
    }
});
server.start();
```

### 下发控制命令
```java
// 启动总线设备
YwnServer.sendControl(deviceNumber, YwnFrame.busStart(deviceNumber, 1, 1, 222));

// 消音
YwnServer.sendControl(deviceNumber, YwnFrame.silence(deviceNumber, 1));

// 手自动转换(3=自动)

```

## 九、与V1.0旧版协议的差异提醒

1. **完全去除Protobuf** — 不再需要.proto文件和Protobuf编解码器
2. **帧头简化** — 从「长度(2B)+命令(2B)+序列号(4B)」简化为「命令码(1B)」
3. **设备编号位置** — 从Protobuf字段移到帧的第2-3字节
4. **事件结构** — 从Protobuf EventReq变为64字节固定二进制结构
5. **心跳周期** — 从30秒延长为3分钟
6. **控制器故障** — 新增0x86/0x87命令，2分钟无数据自动触发
7. **控制命令扩展** — 从10种扩展到17种(新增多线盘/手自动允许禁止等)

## 十、已知限制

1. 无帧校验(CRC/校验和)，数据完整性依赖TCP
2. 无帧长度前缀，解码依赖命令码→帧长度查表，未知命令码可能丢帧
3. 事件数据说明文字为GBK编码，需确保运行环境支持
4. 控制器故障(0x86/0x87)的触发逻辑在服务端实现，非协议层内建
